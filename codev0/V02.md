# Method V0.2 implementation

V0.2 implements a node-level Koopman representation of a learned graph
propagation process. The first local pilot is complete; it does **not** establish
an accuracy improvement over V0.1/GCN. See the web pages
`algorithm_design/docs/methodv02.md` and `algorithm_design/docs/experiments/methodv02.md`.

## Implemented paths

- Reference: `H0 = stem(X, PX, degree)` followed by a shared nonlinear graph
  residual field and its own classification head.
- Deployment: `H0 -> graph encoder -> fixed linear graph RK4 rollout -> nonlinear
  decoder -> classification head`. Reference transitions are never needed here.
- Auxiliary supervision: reconstruct every detached reference state; predict
  horizons 1, 4, 8, T from every valid starting state; align predicted latents with
  detached encodings of the reference future states. Free rollouts do not read
  intermediate reference targets.
- Generator: `ZA0 + PZA1`, with `A0 = S0 - D0 - D1`, `A1 = S1 + D1`, skew `Sj`
  and positive-semidefinite `Dj`. Both matrices receive the same positive norm
  scaling. The continuous generator is dissipative on symmetric normalized
  graphs. RK4 has fixed configuration-dependent substeps and is checked against
  a dense exact matrix exponential on a small graph; this is not an unconditional
  numerical stability theorem.
- Optional periodic `E(D(Z))` uses predicted states only. Default interval zero
  retains pure linear rollout. Auxiliary linearity windows always remain pure.

Reference transitions learn from native classification. All state targets and
auxiliary encoder inputs are detached, so auxiliary losses cannot directly move
the reference dynamics/stem to make fitting easier. The shared stem still learns
from both classification losses, so the reference system changes during training;
joint learning does not guarantee Koopman closure or prevent every degenerate
solution. The frozen-checkpoint perturbation and intervention diagnostics probe
these limitations.

Default loss: proxy CE + native CE + reconstruction NMSE + decoded prediction NMSE
+ 0.1 latent consistency NMSE. Each NMSE uses the detached target's energy with a
floor, not a learned prediction-dependent denominator. Graph features and
unlabeled nodes are used transductively; CE/BCE reads `train_mask` only.

## Run locally

From `/opt/data/private/xzc/work2`, using the existing PyTorch environment:

```bash
/root/anaconda3/envs/torch/bin/python codev0/scripts/run_v02_single_client.py \
  --dataset Cora --client-id 3 --device cuda:0 --epochs 100 --variant joint
```

The local runner creates a new output directory and refuses to overwrite an
existing one. It stores config, validation history, selected model, cost, final
paired test metrics, rollout diagnostics and one held-out feature-perturbation
response. It evaluates test labels after checkpoint selection, not every epoch.

`--variant` supports:

| Variant | Trained objective / executed path |
| --- | --- |
| `joint` | Full V0.2 |
| `identity` | Retrain full losses with K = I; no correction |
| `no_dynamics` | Retain both classification losses and AE reconstruction, remove prediction/linearity losses |
| `no_aux` | Proxy classification only; reference field is untrained |
| `native` | Nonlinear reference classifier trained independently |
| `v01` | Existing V0.1 model, trained with this runner's protocol |
| `gcn` | Two-layer PyG GCN, hidden 64, ReLU, dropout 0.5 |

The selected model also receives inference-only identity/zero-latent/correction
interventions. These differ from retraining an ablation and do not select a model.

```bash
/root/anaconda3/envs/torch/bin/python codev0/scripts/summarize_v02_pilot.py \
  codev0/run_logs/v02_pilot/Cora_client3_seed42_lr003
/root/anaconda3/envs/torch/bin/python -m unittest discover -s codev0/tests -p 'test_*.py' -v
```

## Federated entry point

Registration and the CPU client/logger integration test are implemented. A full
V0.2 federated experiment has **not** been run. The configuration resolves to
100 rounds and **one local epoch** for Cora and CiteSeer. The existing full-model
aggregation and persistent client Adam state are reused. Training-only reference
modules are currently included in the federated payload; no small-K communication
or Bayesian adaptation claim is made.

```bash
/root/anaconda3/envs/torch/bin/python codev0/main.py \
  --model v02_koopman --dataset Cora --gpu 0,1 --n-workers 2 \
  --n-rnds 100 --n-eps 1 --run-tag v02_initial
```

## Reference provenance and limits

- DeepKoopman: local `GitHub/DeepKoopman/networkarch.py::create_koopman_net` and
  `training.py::define_loss` motivate reconstruction, decoded future prediction,
  and latent consistency. This is a fresh PyTorch graph implementation, not a
  copied TensorFlow model or a reproduction of the paper's results.
- Balanced Neural ODEs: local `bnode_modules.py::LatentODEFunc` informs continuous
  latent evolution. Our dissipative graph generator and spectral-entropy effective
  rank are our own design/diagnostics, not B-NODE's VAE or KL-based pruning.
- Course Correcting: optional periodic predicted-state reencoding follows the
  previously documented paper mechanism. No official implementation was available
  in the downloaded reference set.
- MetaKoopman: operator-posterior adaptation remains deferred until meaningful
  transition pairs and shared coordinates are validated.

The current model uses static-graph propagation depth, not observed physical time.
Its pure latent deployment remains a constrained linear graph filter between
nonlinear encoding and decoding. Trajectory supervision gives this representation
a falsifiable dynamics target; it does not by itself prove greater expressivity
than a general nonlinear GNN or better node-classification accuracy.
